1. INTRODUCTION                                           *lvim-utils-intro*

lvim-utils is the BASE plugin of the lvim-tech set — the shared foundation
every other plugin builds on. It owns:

  - the live colour palette (|lvim-utils-colors|), synced from lvim-colorscheme,
  - the central highlight-group factory (|lvim-utils-highlight|), read BY NAME
    by every other plugin, self-theming on every ColorScheme change,
  - the canonical cursor-hiding mechanism (|lvim-utils-cursor|),
  - the ecosystem-wide mouse-selection lock (|lvim-utils-mouse|),
  - the foreground-dim / darken primitives + the surface backdrop
    (|lvim-utils-dim|),
  - the dock-stack manager (|lvim-utils-dock|) + the :LvimDock command,
  - the unified persistence store — file/json/sqlite (|lvim-utils-store|),
  - an icon-provider facade (|lvim-utils-icons|) and shared helpers
    (|lvim-utils-utils|).

Requires Neovim >= 0.12. The former ui/notify/msgarea/picker/dashboard/cmdline
/chrome/gx modules moved to their OWN plugins in the monorepo split — see
|lvim-utils-split|.

2. SETUP                                                  *lvim-utils-setup*

setup() is optional and configures ONLY the base — it merges the palette + the
base config in place (via |lvim-utils-utils|'s merge), self-themes the group
map from the fully-configured palette, and installs the cursor / dock / mouse
layers. Readers of `require("lvim-utils.config").<key>` see the effective
values.
>lua
  require("lvim-utils").setup({
      colors = {},              -- palette overrides (sticky over syncs)
      highlights = {},          -- highlight-group overrides, applied hard

      cursor = {                -- lvim-utils.cursor
          ft = {},              -- transient popups: hide whenever visible anywhere
          panel_ft = {},        -- side panels: hide only while CURRENT window
          hide_on_cmdline = false,
      },

      section = {               -- global fold-header tinting
          tint = 0.1,
          tint_hover = 0.2,
      },

      dock = {                  -- the dock-stack manager
          enable = true,
          keys = {
              cycle_next = "<Leader>n",
              cycle_prev = "<Leader>p",
              close = "<Leader>x",
              menu = "<Leader>m",
          },
          default_layout = "area",
          capture_leader = true,
          geometry = {
              float = {
                  height = 0.7, width = 0.9,
                  height_auto = true, width_auto = false,
                  backdrop = { enabled = true, mode = "dim",
                      dim = { amount = 0.4 }, darken = { amount = 0.3 } },
                  keep_focus = false, auto_hide = true,
              },
              area = {
                  height = 0.5, height_peek = 0.7, height_auto = true,
                  backdrop = { enabled = true, mode = "dim",
                      dim = { amount = 0.4 }, darken = { amount = 0.3 } },
                  keep_focus = true, auto_hide = false,
              },
              bottom = {
                  height = 0.5, height_peek = 0.7, height_auto = true,
                  backdrop = { enabled = true, mode = "dim",
                      dim = { amount = 0.4 }, darken = { amount = 0.3 } },
                  keep_focus = true, auto_hide = false,
              },
          },
      },

      -- ui: the shared chrome theme spec (every tint strength + accent the UI
      -- paints with, named by role). See lua/lvim-utils/config/ui.lua for the
      -- complete default table; every value is overridable here.
      ui = { tint = {}, accent = {}, title = { accent = "blue", tint = 0.2, tint_hover = 0.3 } },
  })
<
TINT = how far an accent is blended toward the panel background (0 = plain bg,
1 = the pure accent). ACCENT = a palette KEY (tracks the live theme) or a
literal "#rrggbb". The full ui defaults live in the plugin's config/ui.lua and
in README.md.

3. COLORS                                                 *lvim-utils-colors*

The public colour palette. Bundled muted dark/light palettes are used
standalone (swapped on &background change); when lvim-colorscheme is present
the palette syncs from the active theme (and follows its `transparent` state).
setup({ colors = {...} }) overrides are STICKY — re-applied over every base
swap and theme sync.
>lua
  local c = require("lvim-utils.colors")
  local red = c.red            -- "#cb4f4f"
  local mixed = c.blend(c.teal, c.bg, 0.3)
<
                                                          *lvim-utils.colors*
setup(overrides)        Override palette colours; re-applies over an
                        already-synced theme, then notifies listeners.
sync_from_lcs()         Pull the palette from lvim-colorscheme, fire on_change.
on_change(fn)           Register a change callback; returns an unsubscribe fn.
blend(fg, bg, alpha)    Blend two hex colours (alpha 1.0 = fully fg).
lighten(color, amount)  Blend toward white.
darken(color, amount)   Blend toward black.

4. HIGHLIGHT                                            *lvim-utils-highlight*

The group registrar. Defines / links groups, and BINDS a factory that rebuilds

                                                       *lvim-utils.highlight*
blend / lighten / darken        Blend helpers (re-exported by colors).
define(name, opts)              Define a highlight group.
define_if_missing(name, opts)   Define only if not already present.
link(name, link_to)             Link a group to another.
get(name) / group_exists(name)  Read a group / test its existence.
clear(name)                     Clear a group.
register(groups, force)         Register a table of groups (force = apply hard).
bind(fn)                        Bind a factory fn(colors)->groups; re-run on
                                palette change.
setup()                         Install the ColorScheme autocmd.
section_accent(accent)          The tinted band for a collapsible fold header.
band_line(parts, sep)           Build a full-width tinted band line.

5. CURSOR                                                 *lvim-utils-cursor*

Hides the hardware cursor whenever a buffer with a REGISTERED filetype owns the
screen, via a dedicated LvimUtilsHiddenCursor group (blend=100, 1-cell bar) —
imperceptible in GUI and TUI with 'termguicolors'. This is the ONE cursor
system; every lvim-tech popup / panel delegates here. Two lists:

  ft        transient popups — hidden whenever such a buffer is visible in ANY
            window.
  panel_ft  persistent side panels — hidden ONLY while the panel is the CURRENT
            window.

Self-registration is preferred: a plugin registers its own panel filetype from
its own setup():
>lua
  require("lvim-utils.cursor").register({ panel_ft = { "my-panel" } })
<
register() ALSO feeds the live config.cursor registry, so the |lvim-utils-mouse|
selection-lock sees the panel automatically — even one that never goes through
a surface chassis.

                                                         *lvim-utils.cursor*
setup(opts)                     Register filetypes and install the autocmds.
register({ ft, panel_ft })      Add filetypes at runtime (extends; no rebuild).
update()                        Force-refresh cursor state.
mark_input_buffer(buf, v)       Keep the cursor visible in buf.
mark_hide_buffer(buf, v)        Hide while buf is current, by handle.
mark_cursor_buffer(buf, frag)   Custom 'guicursor' fragment while buf current.
set_cmdline_hide(v)             Hide the cursor while the command-line is active.

6. MOUSE                                                   *lvim-utils-mouse*

The ecosystem-wide MOUSE-SELECTION LOCK for UI panels. A panel is a rendered
surface, not text — a mouse click there must never start Visual (a fast click
emits <2-/3-/4-LeftMouse>, which natively select word/line/block and replace
the row's cursorline bar with a Visual patch over the label). The lock is
GLOBAL (a buffer-local map only fires when the panel is already current — the
wrong case): global `expr` maps decide by the window UNDER THE POINTER. It
reads the same registry |lvim-utils-cursor| uses.

                                                          *lvim-utils.mouse*
setup()                     Install the global lock (from lvim-utils.setup).
lock(buf, opts)             Mark buf a locked panel; opts.scroll nops the wheel.
register_click(buf, fn)     Register a row-click handler fn(line,col0,pos,count).
should_swallow()            True when the current mouse event is over a locked
                            panel — call FIRST from any global mouse map.
defer_activation(fn)        Defer a window-switching activation until release.
flush_activation()          Run (and clear) a deferred activation.

7. DIM                                                       *lvim-utils-dim*

Foreground-dim primitives: a highlight NAMESPACE whose groups are the global
highlights with their FOREGROUND muted toward the editor background
(backgrounds untouched, so it coexists with `transparent` and never hides a
terminal-composited image underneath). `build` dims fg; `darken` mutes fg+bg
toward a dark colour. The focus-aware surface BACKDROP mutes every window
behind an open surface and lifts as focus moves out.

                                                            *lvim-utils.dim*
build(bg_hex, amount, ns?)      (Re)build a dim namespace; returns the ns.
darken(dark_hex, amount, ns?)   (Re)build a darken namespace (fg+bg).
set(win, ns?)                   Switch win onto ns (or back to 0).
preserve(pattern)               Leave matching groups unmuted (data-fg).
blend(fg, bg, t)                Numeric (0xRRGGBB) blend.
apply_backdrop(id, cfg)         Apply a focus-aware backdrop behind a surface.
clear_backdrop(id)              Tear a backdrop down, restoring every window.
refresh_backdrop()              Rebuild every backdrop ns from the live palette.
suspend(on) / on_suspend(cb)    Suspend/resume per-window dim managers.
hold_backdrop(on)               Freeze focus reconciliation across a transition.
release_backdrop_when_settled() Release the hold once focus has settled.
transition_active()             Is a hold in progress?

                                                   *lvim-utils-dim-backdrop*
The `cfg` handed to apply_backdrop(): >lua
    {
        enabled = true,       -- false → no backdrop (same as clear_backdrop)
        mode = "dim",         -- "dim" (fg toward bg) | "darken" (fg+bg → black)
        amount = 0.5,         -- mute fraction 0..1
        bg = nil,             -- blend target (default: the live Normal bg)
        protect = function(win) end,      -- win is the consumer's → never muted
        focus_keeps = function(win) end,  -- wider: keep the veil while current
        dim_panels = false,   -- also mute special-buftype panels (not terminals)
    }
<
                                                       *lvim-utils-dim-hold*
Reconciling focus on every |WinEnter| is right while a surface sits there, and
wrong while one surface REPLACES another: focus passes transiently through the
editor mid-swap, the veil lifts, and the user sees a flash. A consumer that
tears one surface down and opens another wraps the swap: >lua
    dim.hold_backdrop(true)
    -- … close the old surface, open the new one …
    dim.release_backdrop_when_settled()
<
release_backdrop_when_settled() waits for focus to rest on a PROTECTED window
(the primary signal) and falls back to a timer only if that never happens, so
the editor can never be left permanently dimmed. `focus_keeps` covers the
narrower case of a consumer that legitimately focuses a window it does not own
(a preview, an input popup) without lifting the veil.

This is a CONSUMER-SIDE seam — lvim-ui.surface and the pickers use it; ordinary
callers need only apply_backdrop() / clear_backdrop().

8. DOCK                                                     *lvim-utils-dock*

The dock-stack manager: coordinates the three docking layouts (area / bottom /
float) so at most ONE consumer is visible per layout, each layout keeps its own
MRU stack, and a key cycles the visible one. Every docked / floated surface
reads its geometry (size + backdrop + focus behaviour) through
dock.slot(layout) — no plugin keeps its own size. See |lvim-utils-setup| for
the `geometry` defaults.

                                                           *lvim-utils.dock*
setup(opts)                     Bind the global cycle keymaps per live config.
register(consumer)              Register a dock consumer + its callbacks.
open/show/hide/close(key)       Drive a consumer's visibility.
close_current(layout)           Kill the visible consumer of a layout.
cycle(layout, dir)              Cycle the visible consumer.
menu(layout)                    Open a select of every live consumer.
reveal(layout) / descend()      Reveal a layout's stack / descend a consumer.
visible/stack/entries           Query visible key / a stack / all entries.
slot(layout, opts)              Resolve a layout's geometry to a rect.
set_slot_provider / set_handoff Register the area-zone provider / file handoff.
closed/dropped/parked(key)      Report a self-dismissal (see the parking rules).
register_tab / unregister_tab   Register a full-tab WORKSPACE (fourth layout).
reveal_tab() / cycle_tab(dir)   Reveal the last-used workspace / step through.

                                                    *lvim-utils-dock-parking*
A consumer that closes its OWN window (`q`, `:q`, |WinClosed|) reports it with
closed() / dropped() / parked(). With `keep_closed = true` (the default) such a
SOFT DISMISS PARKS a consumer whose state survives the teardown (`is_alive()`
true — e.g. a panel backed by a registry): the entry stays on its stack, at the
top, re-summonable from the `<Leader>m` menu or by cycling, and closed()/
dropped() return `true` so the consumer keeps its dock key. A non-restorable
consumer (a finished process) is removed instead.

The explicit `<Leader>x` KILL (close()) ALWAYS removes — it is the escape hatch
that forgets a parked entry. Parking also drops the buffer-local `<Leader>`
owner: a parked consumer's buffers may outlive its window, and such a buffer
must not keep swallowing leader chords. Re-showing reinstalls it.

                                                       *lvim-utils-dock-tabs*
Beyond the three occlusion stacks, a consumer that owns a WHOLE tabpage (a
full-screen workbench) registers as a WORKSPACE. Workspaces COEXIST rather than
occlude — the tab layout has no one-visible-per-layout rule — so they get their
own reveal/cycle and appear as a fourth tab in the unified menu: >lua
    require("lvim-utils.dock").register_tab({
        id = "lvim-rest",                       -- stable identity
        name = "REST workbench",                -- menu label
        icon = "󰖟",                              -- optional glyph
        show = function() end,                  -- FOCUS its tab, else RESTORE it
        is_current = function() end,            -- is it the current tabpage?
        is_alive = function() end,              -- still listable? false → dropped
    })
<
Registration order is the cycle order, and is stable across re-registration.

                                                                  *:LvimDock*
:LvimDock                       The unified TABBED menu (area/bottom/float/tab).
:LvimDock menu                  The same.
:LvimDock {layout}              Reveal that layout's current dock — or, for
                                `tab`, the last-used workspace.
:LvimDock {layout} menu         A single-list menu scoped to that layout.
:LvimDock {layout} next         Cycle that layout forward.
:LvimDock {layout} prev         Cycle that layout back.

{layout} is `area`, `bottom`, `float` or `tab`; every token completes.

9. STORE                                                   *lvim-utils-store*

One persistence model, THREE backends, plus mirroring + cross-instance sync — a
declarative live table: declare fields, then read / assign them directly;
assignment auto-persists (and auto-mirrors). A `nil` assignment CLEARS the
field on every backend (it falls back to its declared default on reload).

  file    a flat key=value text file (string values, readable early). Atomic.
  json    one JSON document (typed / nested Lua data). Atomic.
  sqlite  relational tables + CRUD + versioned migrations (needs sqlite.lua).
>lua
  local s = require("lvim-utils.store").new({
      backend = "sqlite", name = "control-center",
      fields  = { colorscheme = "lvim_dark", opacity = 0.9 },
      mirror  = { colorscheme = vim.fn.stdpath("config") .. "/.theme" },
      watch   = true,
      on_change = function(all) end,
  })
  s.colorscheme = "lvim_light"   -- persists + writes the .theme mirror
  s.opacity = nil                -- CLEARS the field
<
Dependency-free EARLY reads open no store:
>lua
  require("lvim-utils.store").read_file(path)       -- a mirror's raw value
  require("lvim-utils.store").read_json(path, key)  -- a value from a json store
<
                                                          *lvim-utils.store*
new(opts)                       Open a store as a declarative live table.
read_file(path)                 The raw first-line value of a plain file.
read_json(path, key?)           Decode a json store file (doc or one key).
available()                     Whether the sqlite backend is available.
health(health, mandatory?)      Report the sqlite backend in :checkhealth.

On the handle: s:save(), s:reload(), s:all(), s:close(), s:is_open(),
s:path(), and (sqlite) s:find/insert/update/remove/count/exec/transaction.

13. HIGHLIGHT GROUPS                                  *lvim-utils-highlights*

lvim-utils.config builds the central highlight-group map (the LvimUi* /
LvimNotify* / LvimUiMsgArea* / LvimUiDashboard* / LvimUiChrome* families) from
the live palette and publishes it as config.colors. It stays in the base
because every split plugin references those groups BY NAME (they don't redefine
them) — one theming source of truth. setup() binds the factory via
highlight.bind, so the whole map self-themes on every palette / ColorScheme
change; the accents and tints are the `ui` config (|lvim-utils-setup|).
