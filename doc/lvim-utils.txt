1. INTRODUCTION                                           *lvim-utils-intro*

lvim-utils is the shared foundation for the lvim-tech plugins. It provides:

  - a single color palette (|lvim-utils-colors|) that syncs from lvim-colorscheme,
  - a self-theming highlight engine (|lvim-utils-highlight|) every plugin uses to
    color its own UI from that palette while staying overwritable,
  - a floating popup toolkit (|lvim-utils-ui|): select, multiselect, input, tabs, info,
  - a notification system (|lvim-utils-notify|) and a docked message/picker zone
    (|lvim-utils-msgarea|), plus cursor, gx, quit, cmdline, input and misc helpers.

It has no hard dependency on lvim-colorscheme: absent it, the bundled muted palette
is used and every group still renders.

==============================================================================
2. SETUP                                                  *lvim-utils-setup*

One `setup()` configures every module. All keys are optional.
>lua
  require("lvim-utils").setup({
      colors = { red = "#ff5555" },   -- palette overrides (see |lvim-utils-colors|)
      highlights = {},                -- explicit highlight overrides (applied hard)
      ui = {},                        -- popup config (see |lvim-utils-ui|)
      cursor = { ft = { "neo-tree" } },
      gx = {},
      notify = {},                    -- false to disable
      cmdline = { enable = true },    -- opt-in self-rendered cmdline
      input = {},                     -- vim.ui.input dispatcher; opt-in
  })
<
Order: palette overrides are applied first, then module configs, then the UI groups are
bound (|lvim-utils-self-theming|), then palette sync from lvim-colorscheme is activated.

==============================================================================
3. SELF-THEMING                                    *lvim-utils-self-theming*

Every lvim-tech plugin themes its OWN highlight groups from the shared palette, instead
of relying on a colorscheme to define them. The rule:

  - groups must EXIST under any colorscheme (derived from |lvim-utils-colors|), and
  - groups must be OVERWRITABLE — a colorscheme that defines them, or the user, wins.

Use |lvim-utils-highlight| `bind`:
>lua
  local hl = require("lvim-utils.highlight")
  local c = require("lvim-utils.colors")
  hl.bind(function()
      return { MyPluginTitle = { fg = c.blue, bold = true } }
  end)
<
`bind` applies the factory's groups with `default = true` (overwritable) and re-applies
them automatically on palette change and on |ColorScheme|. When the palette actually
changes (theme switch or live preview) the groups are force-updated so the new colors
take effect — a plain `default` re-apply would be a no-op once the group exists.

lvim-colorscheme does NOT ship the lvim-tech plugins' groups; each plugin owns its look
through `bind`. lvim-colorscheme still themes EXTERNAL plugins (telescope, gitsigns, …).

4. COLORS                                                *lvim-utils-colors*

The public palette, shared by every module and external plugins.
>lua
  local c = require("lvim-utils.colors")
  c.red        -- "#cb4f4f"
  c.bg_light   -- "#2c3339"
  c.git.add    -- "#5f7240"
  c.blend(c.teal, c.bg, 0.3)
<
It auto-syncs from lvim-colorscheme when present (on |User| `LvimColorscheme`), so the
palette — and every `bind`-ed group — follows the active lvim theme live. Standalone
(no lvim-colorscheme), a bundled muted DARK and LIGHT palette is used and swapped
automatically on `&background` change. `setup({ colors = {...} })` overrides are sticky:
they are re-applied on top of every background flip and theme sync.

                                                  *lvim-utils-colors-api*
setup({overrides})          Override palette colors (derived ones recomputed).
sync_from_lcs()             Pull the palette from lvim-colorscheme and fire on_change.
on_change({fn})             Register a callback fired whenever the palette changes.
blend({fg}, {bg}, {alpha})  Blend two hex colors (alpha 1.0 = fully fg).
lighten({color}, {amount})  Blend toward white.
darken({color}, {amount})   Blend toward black.

5. HIGHLIGHT                                           *lvim-utils-highlight*

The self-theming highlight engine and color helpers.

                                                  *lvim-utils-highlight-api*
bind({fn})                  Self-theme: apply a palette factory with `default = true`,
                            re-applied on palette / |ColorScheme| change (the canonical
                            self-theming entry point — see |lvim-utils-self-theming|).
                            `fn` receives the live palette; returns a dispose function
                            that unbinds the factory.
register({groups} [,force]) Register and apply FIXED groups (not palette-derived).
                            force = true always applies, else only when unset.
setup()                     Install the |ColorScheme| autocmd (call once).
blend({fg}, {bg}, {alpha})  Blend two hex colors.
lighten({color}, {amount})  Blend toward white.
darken({color}, {amount})   Blend toward black.
define({name}, {opts})      Set a group (always).
define_if_missing(...)      Set a group only if unset.
clear({name})               Reset a group to empty.
get({name})                 Get group attributes, or nil.
link({name}, {to})          Link one group to another.
group_exists({name})        Whether a group is defined (non-empty).

6. UI                                                        *lvim-utils-ui*

Floating popup components, all sharing one visual style driven by the highlight groups.
Modes: `select`, `multiselect`, `input`, `confirm`, `tabs`, `info`.
>lua
  local ui = require("lvim-utils.ui")
  ui.select({ items = { "One", "Two" }, callback = function(ok, res) end })
  ui.confirm({ prompt = " Delete?", callback = function(yes) end })
  ui.tabs({ tabs = { { label = "A", items = {...} } }, callback = function(...) end })
<
`ui.confirm{ prompt, yes?, no?, default_no?, callback = fun(yes) }` is a yes/no dialog;
cancelling resolves to `false`.
`subtitle` is a message line under the title — a string, ONE table
`{ text, type?, hl?, icon?, blank_below? }`, or a LIST of them (multi-line). `type` ∈
"info" (blue) | "warn" (orange) | "error" (red), all fg-only; `hl` overrides; `icon`
is fronted when given; `blank_below` adds an empty row beneath.
The tabs header bar and the footer hint bar scroll / wrap to fit a narrow popup: the tab
bar windows around the active tab (with `  ` chevrons for hidden tabs) and the footer
hints wrap into an aligned column grid. See the README for the full per-mode option
reference, `ui.new()` isolated instances, and popup positioning.

  Default popup keys ~
  j / k          Move          h / l          Switch tab (tabs mode)
  <CR>           Confirm        <Esc> / q      Close

                                                       *lvim-utils-ui-frame*
FRAME BORDER & TITLE ~

Six `ui` config keys are the single source of truth for the windowed-UI "frame".
EVERY panel across all lvim-tech plugins (pickers, ui.tabs panels, lvim-lsp hover /
diagnostic peeks, lvim-space, the control center, …) now resolves to them, so
changing one key re-borders or re-titles the whole set on the next open.

  `border`         THE CONTAINER frame, a full 8-cell border { topleft, top, topright,
                   right, botright, bot, botleft, left }. Default { "", " ", "", "", "",
                   "", "", "" } — ONLY a top " " bar carrying the title + counter; no
                   side/bottom ring (the group_border frames the panels). Set a full
                   ring to box the whole container.
  `content_border` THE per-panel ring — drawn around EACH DATA block INSIDE the container
                   (a picker's list + preview, the tabs content). Independent of `border`
                   and `group_border`. Default "none" (panels BORDERLESS): the group_border
                   frames the two panels and the separator divides them, so a per-panel ring
                   would double the lines. Set an 8-element ring to frame each panel too.
  `group_border`   THE one canonical GROUP ring — a COMMON frame around the DATA panels
                   as a group (a picker's list + preview together), INSIDE the container
                   but OUTSIDE the header / footer nav bands. The third "unifying" ring:
                   container › group › each panel's content_border. Drawn ONLY with ≥2
                   panels; a 1-col gutter sits between container↔group and group↔panels
                   so no edge doubles. `{ …, hl }` table, or false to disable.
  `separator`      THE one canonical INTER-PANEL divider — the rule BETWEEN adjacent
                   content panels. A { h, v, hl } table: `h` ("│") side-by-side, `v`
                   ("─") stacked (auto-oriented), `hl` the tint (default the border
                   tint). Drawn only at n-1 gaps, so a single-panel surface shows
                   none. `separator = false` disables it; a plain string = both axes.
  `title_line`     "row" (default) | "border" | "statusline". Where a frame's TITLE
                   goes: a top CONTENT row drawn from column 0 (flush-left title,
                   flush-right counter), the native border-title (needs a top border,
                   which the default border="none" lacks), or the chrome statusline
                   overlay (area only, minibuffer style).
  `title_pos`      "left" (default) | "center" | "right". Title ALIGNMENT, honoured by
                   both the content-row title and the native border-title. "left" =
                   title flush-left + counter flush-right; "center"/"right" place the
                   title accordingly (counter stays right). Lets a panel centre its
                   title with no border.
  `counter`        "title" (default) | "footer". Where a supplied count renders:
                   RIGHT-aligned on the SAME top-border line as the title
                   ("NAME ………… 8/62"), or a right-aligned native bottom border-FOOTER.

A single `surface.open` / presenter call may override any of these per-open; the
config defaults govern every consumer otherwise.

                                                          *lvim-utils-ui-peek*
PEEK ~

`ui.peek(opts)` is a two-pane location navigator: a COLLAPSIBLE list of source locations
grouped by file on one side, a LIVE preview of the focused location on the other. Only the
group holding the focus is expanded (rows are plain text, no line numbers); the preview
shows the real buffer WITH line numbers, so syntax / treesitter highlighting comes for
free. `opts.mode` chooses the look — `"split"` (embedded splits at the bottom) or `"float"`
(detached floating container with an optional dimmed backdrop). >lua
  require("lvim-utils.ui").peek({
      title = "References",
      mode = "split",                       -- or "float"
      items = {                             -- 1-based lnum/col; end_* optional
          { filename = "/abs/a.lua", lnum = 12, col = 7, end_col = 18, text = "…" },
          { filename = "/abs/b.lua", lnum = 3,  col = 1, text = "…" },
      },
      on_jump = function(item, cmd) end,    -- optional; cmd = edit|split|vsplit|tabedit
  })
<
Items group by `filename` (header = fold icon + name in green + directory in
yellow + a bracketed `[count]` in the ACTIVE filter's colour); returns false when
empty. A filter with no matches shows a "No <Filter> <kind>" message (in that
filter's colour) instead of a blank list, and the preview clears.
`ui.peek.expand` is "auto" (only the focused group open,
follows the cursor) or "manual" (toggle groups by click / <CR> on a header).
Keys: j/k move, <Tab>/<S-Tab> file groups, <CR> open (or fold a header in
manual), s/v/t split/vsplit/tab, <C-l>/<C-h> switch pane, f cycle the filter
bar's primary group, q close; the focused pane's keys also ride the container's
bottom-border footer. The mouse works too (single-click select / fold / toggle
a filter button, double-click open, drag horizontally to resize the split). The
left/right ratio is `list_width` (a fraction of the region — 0.4 = 40% list /
60% preview — or absolute cols when > 1); `list_position` picks the side.
Configured under `ui.peek` (mode, expand, list_position, list_width,
preview_height, preview_number, float, border, list_border, preview_border,
  title, footer, group_icon_open, group_icon_closed, guide_icon, keys).

An item may also carry `icon` + `icon_hl` (a glyph before the row text, e.g. a
severity sign) and a free `severity` tag for filter predicates.

FILTER BAR ~

`opts.bar` adds a row of toggle buttons centred on the whole panel under the
title, installer-style with a bracketed hotkey letter per button
([A]ll 5 [E]rror 2 [W]arn 1 …). Each button GROUP tracks one active button; the
effective filter is the AND of every group's active-button `predicate(item)`. A
button's bracketed letter (its `key`, else the label's first letter) jumps to it;
clicking it, or `f` to cycle the `primary` group, also works — all re-filter the
list LIVE without reopening, each button showing its live count. Buttons may set
`hl` / `hl_active` to paint themselves in their own accent. The lvim-lsp
diagnostics navigator uses this for its Workspace/Buffer scope + All/Error/Warn/…
severity filters. >lua
  bar = {
      groups = {
          {
              id = "severity", active = "all", primary = true,
              buttons = {
                  { id = "all",   label = "All",   predicate = function() return true end },
                  { id = "error", label = "Error", predicate = function(it) return it.severity == 1 end },
              },
          },
      },
  }
<

7. NOTIFY                                                *lvim-utils-notify*

Notification system with toast panels, a history pager, progress channels and pluggable
printers.
>lua
  local n = require("lvim-utils.notify")
  n.notify("Saved", vim.log.levels.INFO)
  n.notify("Failed", vim.log.levels.ERROR)
<
Identical consecutive toasts are collapsed into one with a `×N` badge (config
`notify.dedup = true`, on by default), and the auto-dismiss timeout slides so a repeating
toast persists while it keeps firing. See the README for progress channels, custom
panels/printers and config.

8. CURSOR                                                *lvim-utils-cursor*

Hides the hardware cursor based on the visible/current buffers' filetypes (via the
`LvimUtilsHiddenCursor` group, blend=100). The ONE cursor system — the `ui` frame
engine delegates its cursor hiding here. Two lists:
  ft        hide whenever such a buffer is visible in ANY window (transient popups)
  panel_ft  hide ONLY while that buffer is the CURRENT window (persistent side panels)
`mark_input_buffer(buf, true)` keeps the cursor VISIBLE in an input field.
`mark_hide_buffer(buf, true)` HIDES the cursor while that buffer is the current
window — by handle, for floats whose filetype is shared (e.g. a markdown hover)
and so cannot be registered via `panel_ft`.
>lua
  require("lvim-utils.cursor").setup({
      ft = { "lvim-ui-frame", "neo-tree" },
      panel_ft = { "lvim-lsp-outline" },
  })
<

14. MSGAREA                                              *lvim-utils-msgarea*

A persistent, toggleable zone docked at the BOTTOM of the screen (a float over the
`cmdheight` region, so a global statusline stays above it). It is a vertical stack of
named SEGMENTS ordered by priority (low = top, high = bottom); every owner puts content
in through a segment and the core composes them. Three are built in: messages (routed
notifications), the completion grid (blink's list, rendered here), and the unified
command line. Enable via `setup({ msgarea = { enable = true } })`; toggle with
`:LvimMsgArea`. The zone is hidden whenever the stack is empty.

The zone renders through a single ui.surface (|lvim-utils-ui|, `position = "cmdline"`) — the
one layout chassis shared with the float finders / docks — which grows `cmdheight` so a
global statusline stays above it. Focused interaction (M.focus) drives that same panel.

PUBLIC SEGMENT API                                   *lvim-utils-msgarea-api*

`require("lvim-utils.msgarea").segment(name, opts?)` returns a HANDLE (get-or-create by
name; `opts` = `{ priority?, kind? }`). Every method reflows the zone:
>lua
  local ma = require("lvim-utils.msgarea")
  local h = ma.segment("my-plugin", { priority = 60 })
  h:set(lines, hls)                    -- plain lines + parallel highlights
  h:set_grid(items, sel, opts)         -- grid of { text, icon?, icon_hl?, match? }
  h:select(idx)                        -- cheap selection-only update (grid)
  h:provider(function(width) end)      -- lazy lines, re-rendered each paint
  h:refresh()                          -- force a re-render (provider data changed)
  h:reserve(height)                    -- blank rows for an external float; returns a rect
  h:title("Results")                   -- a header row above the segment
  h:clear()                            -- empty the content (keep the segment)
  h:release()                          -- remove the segment entirely
<
`match` (grid items) is a list of 0-based char indices into `text` to highlight. blink
fills it from its fuzzy; other consumers compute it with
`require("lvim-utils.utils").match_indices(query, text)`.

INTERACTION                                          *lvim-utils-msgarea-focus*

When the zone is focused, one segment is active and takes the keyboard:
>lua
  ma.segment("picker")
    :set_grid(items, 1, { columns = 2 })
    :on_confirm(function(item, idx) ma.blur() end)  -- <CR>
    :on_move(function(idx) end)                      -- selection moved
    :keys({ d = function(handle) end })              -- custom keymaps while focused
    :focus()                                          -- M.focus(name) / M.blur()
<
On a grid: h/j/k/l (and arrows) move the selection (columns-aware), <CR> fires on_confirm,
<Esc> blurs. On a non-grid (messages) segment those keys stay native, so the scrollback
scrolls. blink mirrors from the command line and is never focused, so the two never collide.

INTEGRATIONS                                  *lvim-utils-msgarea-integrations*

Per-source glue lives in `msgarea/integrations/<plugin>.lua` (an enable()/disable()
module), gated by `setup({ msgarea = { integrations = { <plugin> = true } } })`. blink is
the reference integration.

15. HIGHLIGHT GROUPS                                  *lvim-utils-highlights*

All groups are self-themed from the palette via |lvim-utils-highlight| `bind` and applied
with `default = true` (overwritable). Prefixes:

  LvimUi*        Popup chrome: Normal, Border, Separator, Title, Subtitle, Info,
                 Tab*, Button*, Row*, Item*, Checkbox*, Input, Footer*, Spacer,
                 CursorLine, the cmdline pager groups (LvimUiMsg*), and the message
                 zone groups (LvimUiMsgArea*: Normal/Title/Row*/Sel*/Match/Item*).
  LvimNotify*    Notification panels: Normal, Title, Info/Warn/Error/Debug and their
                 Title*/Header*/Sep* variants.

Override any group explicitly with `setup({ highlights = { GroupName = {...} } })`.

16. HEALTH                                                *lvim-utils-health*

>
    :checkhealth lvim-utils
<
Reports Neovim version, 'termguicolors', whether lvim-colorscheme is driving the palette
(vs the bundled one), whether the UI groups are themed, and ext_cmdline conflicts when the
self-rendered cmdline is enabled.
